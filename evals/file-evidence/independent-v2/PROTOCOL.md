# Independent file-evidence validation v2: frozen protocol

## Purpose, provenance and limits

This is a larger, model-unseen validation set, not a claim of blind human-independent annotation. A/B and transfer-v1 are tuning/regression only. No A/B excerpts or score-driven paraphrases are reused. No v2 provider scoring or classification accuracy was inspected before this freeze. The author selected tasks and labels and wrote the stronger comparators before scoring; this is an explicit limitation. The extended signatures use familiar diagnostic families, not learned thresholds. Do not advertise v2 as sampled real-world CI.

Scouting: eight multi-evidence questions over a shared manifest of 32 whole, variable-length functions from eight CPython 3.11.9 modules. Exact public source URL, full-module SHA-256, function span, extracted text and extract hash accompany each file. PSF attribution/license accompanies the corpus. Every task has two critical gold references. The full manifest is deliberately the same across tasks, not three handpicked distractors. Relevant functions can require additional surrounding class/module context; the helper's eight-line recovery limit is measured as a limitation, not silently replaced with entire functions.

Failure triage: 64 records, including actual failed executions of 24 isolated standard-library Python fixtures and 40 author-created conventional diagnostic examples spanning multiple toolchains, conflicting symptoms, success records and ambiguous terminations. Traceback paths are normalized to basename before publication; no diagnostic lines are deleted. Code and exit status accompany every executed fixture. This is public/synthetic evidence, not private repository logs or customer data. Re-execution may differ by Python version; the frozen diagnostic bytes define validation input.

## Freeze and split

Freeze corpus, protocol, comparator implementation and production evidence/policy code hashes before any v2 provider call. Put the freeze in a local commit. A/B alone can exercise runner plumbing. Do not change labels, thresholds, comparators or selection based on v2 outcomes. If a defect forces a change after scoring, preserve receipts, label that rerun regression and require a new untouched set for promotion. Harness accounting defects may be repaired transparently without changing provider input or classification.

## Predeclared comparisons

Scouting compares exhaustive eligible recovery; shipping lexical top-8 and top-16; identifier-split filename-aware BM25 top-8 and top-16 (k1=1.2, b=0.75); the union of BM25 top-8 and the existing single-excerpt semantic advice; and the union of BM25 top-8 and a benchmark-only eight-question batch. Report semantic-only sets separately. Never interpret unselected or withheld as irrelevant. Relevant files excluded locally count as misses in all-manifest recall and separately in eligible-only recall. Check that every eligible reference really recovers, not just that a manifest entry exists. All full corpus text remains available locally.

Batch is a plumbing/crossover experiment, not a new product endpoint. Screen each recovered excerpt and query under exactly the shipping `public_advice` guards, including path/URL exclusion, then bundle only eligible snippets. Use opaque D0..D7 and questions that explicitly reference the corresponding opaque field; never send file paths, hashes, gold labels or public provenance URLs. Use the existing guarded decide/client/limiter flow, no retries, timeout four seconds, record=False. Apply each shipped file-relevance rule with the unchanged calibrated confidence >=0.85 and margin >=0.4. Unknown/missing/changed version, malformed, failed or unapproved calls abstain. Keep all deterministic references regardless. Shared state means this is NOT identical to independent calls; measure misses and token changes rather than assuming equivalence. No activation based on latency alone.

Triage compares the shipping deterministic classifier, frozen extended conventional signatures, existing local-first semantic pipeline, and extended-code-first semantic advice only for unresolved unguarded failures. Reuse a record's single measured semantic result when applicable, explicitly identifying reuse rather than inventing an additional provider response. Preserve success/failure status, supplied exit code, digest and no-root-cause contract. A semantic category never means the test passed. Do not apply new signatures in production merely because validation favors them.

## Bounded real requests and receipts

Owner authorized this exact public/synthetic evaluation. Existing TypeSafe key resolution only; never read/print/store keys. Verify provider, default endpoint, allowed model and enabled fleet limiter as in v1. At most 100 attempts per shard, 400 across v2, 600 seconds per shard, five consecutive failures, 16000 wire bytes per request. Reserve attempts durably before HTTP; retain per-response actual reported input tokens, bounded model id, latency, sanitized error and list-price estimate. An exhausted budget or limiter abstains, never switches provider or relaxes limits. No credentials, headers or arbitrary provider prose in receipts. Use unique tags, no overwritten or selectively omitted runs. Group receipts by case/mode to count batch and single usage separately. Confirm no missing usage; label unavailable amounts unknown, not zero. There are at most 256 single scouting attempts, 32 batch attempts and 64 triage attempts before guards, below the 400 overall cap.

## Metrics, context and decision

For each comparator: true positives/false positives, precision/recall, all-critical-per-task success, eligible and total coverage, shortlist size, withheld reason counts and abstentions. For triage: exact-match accuracy, known coverage, wrong non-unknown categories, unknown false certainty, abstentions, exit preservation. Include every failure and conflicting case, not merely easy successful labels. Report p50/p95 with defined nearest-rank percentiles and sample counts for end-to-end local/enhanced time and request latency. Paired timings are descriptive, no causal speed claim from sub-millisecond noise. Reused requests are not re-timed as a new call.

Frontier context is a labeled UTF-8 bytes/4 estimate rounded upward per actual JSON delivery, NOT a tokenizer measurement or a frontier bill. Count query, evidence references, shortlisted recovered text, advice/warnings and full eligible manifest metadata, not only text. Compare against exhaustive recovery through the SAME envelope and an explicitly separate optimistic direct-read baseline. Retain serialized delivery byte counts so alternate tokenizers can recompute. Report both a verbose audit delivery (full advice) and a compact caller delivery (id/action/reason only, with complete advice retained locally); neither discards recoverable references. Report Jev's actual provider tokens separately; combined token counts mix counting bases and are estimates. Full-content recovery cost versus the eight-line snippets is reported separately to expose truncation, not charged as if actually read.

Monetary comparison uses repository list-price estimate for Jev, not invoice/verified charges. Report frontier-price break-even as a function of positive estimated frontier tokens avoided, keeping provider cost distinct. If frontier savings <=0, no positive monetary crossover. Net combined context benefit requires (estimated exhaustive frontier input minus enhanced frontier input minus actual Jev input)>0. Show single and batch results separately; amortization does not remove provider tokens.

Promotion requires zero critical scouting misses, no false certainty on unknown/competing failures, no safety regression, meaningful accuracy gain over the strongest deterministic comparator, and positive net context benefit. Those conjunctive bars are not lowered after results. If any fail, decision is NOT_PROMOTED: deterministic-first, skip semantic by default, advisory only, exhaustive evidence recoverable. A savings-positive narrow case is not a general promotion. Skill edits remain blocked by current execution instructions; no source/installed skill modification, merge, gateway restart, routing change or production activation is part of this evaluation.
