# Decision-model portfolio optimization

Use when an owner requests applications across an estate. An inventory is not implementation and a directory is not a verified live product. Load `rightnow-evaluation` for RightNow-specific work.

1. Enumerate the exact authorized project root once, nonrecursively. Persist sorted rows in a private CSV/JSON; count, deduplicate and aggregate programmatically. Include every enumerated row, with explicit unknown/excluded statuses. Never scan the entire home, credentials, customer stores or other-profile conversations.
2. Group apparent duplicate worktrees, references, backups and dated evidence as candidates, not separate active deployments. A name-derived family is a hypothesis. Resolve actual canonical caller/repo/runtime before changing code. Store owner product names and infrastructure paths outside a public reusable skills repository.
3. For each known product family identify the observable decision, approved input class, local deterministic alternative, model fallback, failure/abstention, measurable benefit and owner-visible acceptance. Rank by expected waste avoided, frequency, privacy, latency and error severity. Do not invent usage/savings metrics.
4. Favor cheap local rules, parsers, image/audio measurements and stable artifact hashes before any API. Send compact redacted public/synthetic evidence, batch independent bounded questions, then invoke an expensive model only where uncertainty matters. Avoid a decision call that costs more or takes longer than the task it replaces.
5. Separate text-only existing-skill compatibility from new image/audio/PDF/video caller integrations. Choice counts and score rubrics may need explicit incompatible status, not automatic decomposition. No generic endpoint substitution, global monkeypatch or silent production fallback.
6. Test held-out labeled outcomes, ambiguous examples, injection-bearing inputs, stale state, missing key, 401/402/429/503/504, partial refusal, malformed/contradictory distributions, budget exhaustion and cancellation. Score cost per accepted-correct decision and tail latency, not headline per-token price. Test the actual caller's live user path before promotion.
7. Prefer one low-risk opt-in pilot, then gated incremental adoption. Keep clinical, finance, deletion, outbound, payments, student/private/customer-data and physical-safety authority outside model decisions. Confidence cannot authorize an action. Never silently move on-device/private functions to cloud inference.

Evidence: private complete inventory, family-level rationale, exact code/skill changes, offline vs live modality matrix, actual invoices/usage when authorized, installed readback and unresolved gates. Proposed applications are not deployed features. Do not label an estate fully optimized until its actual canonical callers have individually passed acceptance.

Provenance: custom workflow from local project discovery and official provider contracts. No external agent instructions or raw vendor installer adopted. No keys, customer records or private project inventory belong in this skill.
