# File evidence and failure triage: frozen evaluation protocol

Protocol v1, declared before implementation measurements. Both features are opt-in advisory CLI helpers. No hook, command gate, compaction or routing default changes.

## Comparisons

Use separate synthetic development fixtures and held-out transfer fixtures. Freeze fixture labels before running scores. Report lexical shortlist recall and missed evidence IDs against an exhaustive eligible-manifest baseline. Excluded files, unreadable files and budget omissions count as unknown, never as irrelevant. Report failure taxonomy accuracy including unknown, coverage on known categories, false certainty on ambiguous errors and preserved failing exit codes. Taxonomy describes observed symptoms, not proven causes.

Offline scripted transport results measure contracts and fallback safety, NOT Jev accuracy. A scripted oracle is explicitly not a held-out model. Keep deterministic baseline, offline scripted responses and live provider measurements in separate fields. Record sample counts and per-row predictions. Never infer latency or savings from scripted responses.

## Promotion before measurement

No promotion from synthetic fixtures. On an owner-approved public/synthetic held-out live set of at least 100 scouting tasks and 100 failure records: shortlist relevant-evidence recall must be at least 0.98, with zero critical evidence misses and no regression against deterministic baseline; taxonomy accuracy at least 0.90, known-category coverage at least 0.80, false certainty on unknown cases at most 0.02. Privacy tests must have zero outbound forbidden strings, malformed/outage cases must preserve deterministic evidence and all failing exit codes. Actual wall latency and billed cost must be measured, not estimated savings. Net benefit must beat the deterministic baseline without relaxing owner approvals or test requirements. Unknown criteria are NOT passes. Poor results leave semantic help off and require a new development round, then a fresh held-out set.

## Live gate

No live call is authorized by installation or this document. First obtain an exact approved public/synthetic dataset, request-count/spend ceiling and provider authorization. A proposed pilot is at most 200 single-request classifications, no retries, at most 2500 input tokens per request. Compute the estimate from the existing ledger price table at run time; enforce the approved cap through the existing limiter. No private/customer records, real failure logs or source trees may be used as a substitute. Existing no-filter compaction default stays unchanged.
